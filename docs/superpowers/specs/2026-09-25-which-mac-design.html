WhichMac

Design spec · 2026-09-25 · repo ~/Developer/which-mac

Problem

When you switch between Macs in Jump Desktop, the machine name flashes once when you connect and is easy to miss. After that, nothing on screen says which Mac you're on.

Goal

After switching machines, one glance at the menu bar tells you which Mac you're on, with no clicks.
FinderFileEditViewGo [OP] MacBook Air M2⌘Wi‑FiThu 14:02

Constraints

  • Apps can only put items in the right-hand group of the menu bar. The item will sit at the left end of that group. You set that once with ⌘-drag and macOS remembers it.
On a notched or crowded menu bar, macOS hides right-hand items that don't fit, and no app can prevent that. We're accepting that risk. If it becomes a problem, the fallback is a floating label drawn over the bar, which is out of scope for now.

Behaviour

  • The item's text is the Mac's Computer Name (Host.current().localizedName, the value in System Settings → General → Sharing). It's plain text in the standard menu bar font, with no icon.
  • No Dock icon and no windows (LSUIElement).
  • Clicking the item opens a menu:
    1. The full name, greyed out, for when the bar truncates it.
    2. A divider line.
    3. Open at Login: the checkmark shows SMAppService.mainApp.status == .enabled, and clicking registers or unregisters. If that fails, the app re-reads the status so the checkmark stays accurate, and logs the error with NSLog.
    4. Quit WhichMac (⌘Q).
  • The app re-reads the name each time you open the menu and updates the item, so a rename shows up without a restart. If the Computer Name can't be read, it shows the host name from ProcessInfo instead.

Components

FilePurpose
Sources/main.swiftThe whole app: an AppDelegate that owns the NSStatusItem, its menu and the Open at Login switch.
Resources/Info.plistApp ID com.ollie.whichmac, LSUIElement = true, needs macOS 13 or later (for SMAppService).
build.shRuns swiftc for arm64 and x86_64, combines them with lipo into one universal binary, assembles build/WhichMac.app and signs it locally with codesign.
install.shRuns build.sh, quits any running copy, replaces /Applications/WhichMac.app, launches it and turns on Open at Login. Safe to run again.
uninstall.shTurns off Open at Login, quits the app and removes it from /Applications.
README.mdHow to install, place the item with ⌘-drag and uninstall, plus the note about notched screens.

To turn on Open at Login from install.sh, the app accepts a --enable-login-item flag that registers SMAppService.mainApp when it launches. install.sh runs open /Applications/WhichMac.app --args --enable-login-item.

Out of scope

Custom text or nicknames, colours, the floating label, automatic updates, Apple notarisation.

Testing

There's almost no logic to test, so it's checked end-to-end on this Mac:

  1. ./build.sh succeeds, lipo -archs reports x86_64 arm64, and codesign -v passes.
  2. ./install.sh succeeds, the app is running, and a screenshot of the menu bar shows the computer name.
  3. Open at Login is on after installing: the menu checkmark shows it, and it's listed in System Settings → Login Items.
  4. Running ./install.sh a second time also succeeds.
